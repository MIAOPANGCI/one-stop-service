# 企业服务大厅

把公司内部散落的系统地址——OA、ERP、GitLab、监控、网盘——收拢到一个页面，分类排布，点一下就进。

零第三方依赖，只有 Node.js 标准库；数据存本地 JSON 文件，不依赖任何数据库。扔到一台内网机器上 `node server.js` 就能跑。

## 功能

**导航**
- 服务按分类分组展示，图标墙布局，支持搜索和分类筛选
- 每个服务可配**内网 + 外网两个地址**，自动判断当前网络环境选对的那个
- 图标支持 emoji、文字，或上传自己的图片
- 点开服务有三种方式：新开浏览器标签页 / 当前页跳转 / **在本页用页标签打开**（可多开、可切换）
- 页签栏常驻顶部，第一项固定是「门户」：点它回大厅，开了几个页签一直在眼前；「＋ 打开服务」面板带搜索，服务再多也能快速找到
- 页签显示网页自己的标题（不是域名），鼠标悬停能看到全名；页签多了横向滚动，滚轮也能滚，切换到哪个就自动滚到哪个
- 页签里默认放行 `target="_blank"`（拦掉会让内网系统「点了没反应」，更糟），想安静可在设置里改成拦截
- 同源页面里的 `target="_blank"` 会被接住、直接开成新页签；跨域页面受同源策略限制改不了，只能交给浏览器
- 个别系统内嵌本来就是坏的（依赖同源父页面、或强 `X-Frame-Options`），编辑服务时勾「不内嵌」，它永远走新标签页
- 未登录时首页作为对外门面展示；开了「允许游客直接访问」后游客能浏览和点开服务，但看不到添加、设置，也不能切换内外网，右上角只留一个「登录」

**账号**
- 三级角色：管理员 / 编辑者 / 浏览者
- 密码用 scrypt 加盐哈希存储，任何人（包括管理员）看不到明文
- 「保持登录」可维持 30 天，服务重启不丢登录态
- 同一 IP 连续登录失败 5 次锁定 5 分钟

**外观**
- 日间 / 夜间主题，可跟随系统，偏好存在账号上（换设备也跟着走）
- 日间和夜间可分别设置壁纸，切换主题时自动更换，内置 7 张矢量壁纸
- 支持上传自定义 Logo，自动识别透明底、适配横版比例；浏览器标签页图标由 Logo 自动生成
- 12 套预设主题色 + 48 色调色板 + 任意取色
- 字体可选（默认 / 微软雅黑 / 宋体 / 黑体 / 楷体 / 仿宋 / 等线 / Segoe UI），文字颜色日间与夜间分别设置，留空即跟随主题；次要文字（提示、计数、页脚）由主色派生，不会一半黑一半灰
- 首屏文字按壁纸明暗**自动反色**（浅色壁纸用深色字、顶栏同步反色），阴影可开关、强度 0-100 可调
- 壁纸支持 JPG / PNG / WebP / GIF / BMP / AVIF / SVG，单张 6MB
- 壁纸上的光晕（左上亮斑 + 右下暗角）可以整体关闭，也可以换成任意色系

**数据**
- 所有数据一键导出 / 导入，导出的是 zip，Logo、壁纸、服务图标一起打包
- 数据变更自动备份，保留最近 40 份
- 上传目录自动回收：没人引用的图片会在启动时和每小时各清理一次

## 快速开始

需要 Node.js 16 或更高版本，没有其他依赖。

### Windows

双击 `start.bat`，选启动方式（见下一节）。首次启动会自动创建管理员账号并在控制台打印，同时打开浏览器。

### Linux / macOS

```bash
node server.js
```

启动后控制台会列出所有可访问地址（本机 + 局域网）。

### 首次登录

```
账号：admin
密码：admin123
```

登录后请立即在右上角头像菜单里改掉密码。

## 启动方式

`start.bat` 会先问你要怎么开：

| 选项 | 干什么 | 对应命令 |
|---|---|---|
| 1 仅网页版 | 起服务端 + 打开浏览器，客户端连不进来 | `npm run start:web` |
| 2 仅桌面客户端服务端 | 只起服务端，**不在这里开客户端**，给别的机器上的客户端连 | `npm run start:desktop` |
| 3 两者都启动 | 服务端 + 浏览器 + 本机客户端 | `npm run start:both` |
| 4 只打开桌面客户端 | 连已有的服务端，不起服务端 | `npm run start:client` |
| 5 自定义端口 / 地址 | 先填端口、再填监听地址（留空 0.0.0.0，填 127.0.0.1 只本机，也可填某个网卡 IP），最后选模式 | `node server.js --port 9090 --host 192.168.1.20` |

第 2 项是给服务器用的：**不需要装 Electron，也不需要 `npm install`**，起完这个窗口别关即可，其他机器上装好的客户端填 `http://这台机器:8080` 就能连。

选项 4 需要本机装了客户端（`cd desktop && npm install`，或直接装 exe）；没装的话启动器会提示并跳过，不影响服务端。

模式只决定**谁能连进来**，不改变数据放在哪 —— 一个服务端进程、一份 `data/`，网页版和桌面版读的永远是同一批。

服务端参数：

```bash
node server.js --mode both|web|desktop     # 也可写进 config.json 的 mode，或环境变量 PORTAL_MODE
```

- `both`（默认）：浏览器和桌面客户端都能连
- `web`：只给网页版用，桌面客户端的请求返回 403
- `desktop`：只给桌面客户端用，浏览器打开是一张说明页

区分靠 User-Agent：桌面客户端所有请求都带 `CorpPortalDesktop/<版本>`。

## 桌面客户端（可选）

网页版受同源策略限制，有三件事做不到：对方站点用 `X-Frame-Options` 拒绝被内嵌、页签里的 `target="_blank"` 拦不住、依赖 `parent.$` 握手的老系统会直接抛 `SecurityError`。

`desktop/` 下是一个 Electron 壳，用 `<webview>` 替代 iframe，这三件都能解决。

```bash
cd desktop
npm install        # 首次要下 Electron 运行时，约 100MB
npm start          # 或双击 desktop/start.bat
```

- 壳**不携带、也不启动**后端，所有数据都来自你连接的那个服务端
- 页签容器检测到 `window.desktopAPI` 才用 `<webview>`，**网页版行为完全不变**
- `guest-preload.js` 会把页签页面的 `parent` / `top` 指回自身；个别靠 `window.top !== window` 判断内嵌状态的系统，可用 `PORTAL_NO_SHIM=1` 关掉
- 页签里的 `window.open` 由主进程拦截，转成应用内新页签
- 编辑服务时的「不内嵌」标记只对网页版生效，桌面端会忽略它

### 第一次打开：填服务端地址

客户端只做两件事：连服务端、把服务页面装进页签。它**不启动任何后端**，所以第一次打开会先让你填服务端地址：

- 输入 `http://192.168.3.20:8080` 这种地址，「测试连接」能看到服务端版本
- 点「连接」时主进程会真的探测一次，**连得上才保存**，连不上直接把原因写在窗口里
- 填对了就进大厅；以后启动不再问
- 窗口底部有当前版本号和「检查更新」，连不上服务端时也能先升级客户端

改地址的入口有两个：

- 大厅里「设置 → 打开与网络 → 桌面客户端」
- 菜单「文件 → 重新设置服务端…」（连不上时也进得来）

也可以直接用环境变量跳过引导：`PORTAL_SERVER=http://192.168.3.20:8080`。

因为数据只在服务端那一份，网页版和桌面版看到的永远是同一批；客户端本地不存任何业务数据，唯一落地的是 `%APPDATA%\portal-desktop\desktop-prefs.json`（服务端地址 + 菜单栏显隐）。

### 打包成 exe

```bash
npm run build:desktop
```

会先把根 `package.json` 的版本号同步给 `desktop/package.json`，再交给 electron-builder。产物在 `desktop/dist/`：

| 文件 | 用途 |
|---|---|
| `portal-setup-x.y.z.exe` | 安装包，装一次带桌面快捷方式，推荐 |
| `portal-portable-x.y.z.exe` | 绿色版，双击即用，不写注册表 |

图标取自 `desktop/build/icon-src.png`，`node scripts/make-icon.mjs` 会算好 `icon.png`（256）和 `icon.ico`（16/24/32/48/64/128/256），构建时缺了会自动补。

第一次构建会下载 NSIS、winCodeSign 等工具，走 `ELECTRON_BUILDER_BINARIES_MIRROR` 指向的镜像（脚本里默认 npmmirror）。

**没做代码签名**，同事第一次运行会看到 SmartScreen 提示，点「更多信息 → 仍要运行」即可。

### 菜单栏与下载

- `视图 → 隐藏菜单栏`（Ctrl+Shift+M）关掉顶部那一行，设置记在 `desktop-prefs.json`，下次启动保持；隐藏后按 **Alt** 还能临时叫出来
- 下载时**先弹保存框**，选完才开始下，取消就整条取消
- 多个文件同时下时在同一扇小窗里排队，每条单独可取消，完成变绿、失败变红；不占任务栏、不抢焦点
- 任务栏图标同步显示进度，完成/失败发系统通知，点通知定位到文件

### 更新

客户端不含后端代码，安装包只有 Electron 运行时 + 几个 preload，体积比带后端时小。更新有两条路：

- 启动 5 秒后静默查一次 GitHub Release，连不上就跳过
- 菜单「帮助 → 检查更新」手动查，发现新版本可以「下载并安装」

下载前会问你要哪个版本：**安装版**（带快捷方式，适合长期用）还是**便携版**（单个 exe，不写注册表）。正在跑便携版时会默认推荐便携版。

GitHub 慢或连不上，可以在「设置 → 打开与网络 → 桌面客户端 → 更新下载代理」里填代理（如 `http://127.0.0.1:7897`），也可以设环境变量 `PORTAL_UPDATE_PROXY`。

## 配置

### 端口、监听地址和模式

项目根目录的 `config.json`，首次启动自动生成：

```json
{
  "port": 8080,
  "host": "0.0.0.0",
  "mode": "both"
}
```

- `host` 填 `0.0.0.0` 局域网内都能访问，填 `127.0.0.1` 只有本机，填具体 IP 则只监听那块网卡
- `mode` 取 `both` / `web` / `desktop`，见「启动方式」
- 改完重启服务生效

也可以用命令行参数或环境变量，优先级 **命令行 > 环境变量 > config.json**：

```bash
node server.js --port 9000 --host 192.168.1.100 --mode web
PORT=9000 HOST=0.0.0.0 node server.js
```

桌面客户端还认这些：

| 变量 | 说明 |
|---|---|
| `PORTAL_SERVER` | 服务端地址，等价于在设置里填「连接的服务端」 |
| `PORTAL_NO_SHIM` | 设为 `1` 时不再改写页签页面的 `parent` / `top` |

### 其它环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `ADMIN_USER` | `admin` | 初始管理员账号，只在数据库里还没有用户时生效 |
| `ADMIN_PASSWORD` | `admin123` | 初始管理员密码，同上 |
| `COOKIE_SECURE` | — | 走 HTTPS 时设为 `1`，让会话 Cookie 带 Secure 标记 |
| `PORTAL_DATA_DIR` | 程序目录下 `data/` | 数据目录，桌面端兜底起后端时会指到 `%APPDATA%` |
| `PORTAL_CONFIG` | 程序目录下 `config.json` | 配置文件路径 |
| `DISABLE_UPDATE_CHECK` | — | 设为 `1` 关掉版本检查 |
| `UPDATE_PROXY` | — | 服务端更新检查 / 下载走的代理，如 `http://127.0.0.1:7897` |

## 使用

进大厅后，右上角「+」添加服务（需要编辑权限）：

- **内网 / 外网地址**至少填一个。同名服务在公司和在外面点，会自动跳到对应的地址
- 设置面板左侧分了 6 类：站点 / 壁纸 / 主题配色 / 字体与文字 / 打开与网络 / 数据与权限，一次看一类
- **图标**可以选 emoji、打字，或上传图片（建议正方形 PNG）
- **图标底色**决定图标墙上方块的色调

### 内外网怎么判断

右上角的「内网 / 外网」标签是浏览器在判断，不是服务端 —— 所以同一时刻，办公室的电脑显示内网、手机流量打开显示外网，各自走各自的地址。

判断分三层，前一层得不出结论才走下一层：

1. **配了「内网探测地址」**（设置 → 网络，最多 5 条）：并发请求每个地址，`no-cors` + 1.4 秒超时，任意一个连得上就判内网，全部失败判外网
2. **没配**：拿门户自己的内网地址试一次（服务端把自己的网卡 IP + 端口随接口返回），这个地址一定开着网页端口，外网又访问不到，能连上就说明人在内网
3. **仍不确定**：看当前访问用的主机名，`localhost`、`10.x`、`192.168.x`、`172.16-31.x`、`169.254.x`、`.local`、`.lan` 判内网，其余判外网

第二层不依赖局域网里有没有别的设备，大多数情况到这一步就够了。第三层只是推断 —— 用域名访问（比如 `portal.company.com`）时，人在办公室也会被判成外网。

填什么：内网网关，或任意只有内网能打开的地址。注意探测发的是 **HTTP 请求，不是 ping**（浏览器发不了 ICMP）—— 只响应 ping、没开网页端口的设备**不能**当探测目标，这种情况留空、走第二层就行。设置面板有「用本机内网地址」按钮可以一键填入。

保存前可以点「测试连通」自检，连不上会直接标红。页面如果是 HTTPS，就不能探测 `http://` 地址（浏览器会按混合内容拦掉），按钮会提示。

常用快捷键：

| 键 | 作用 |
|---|---|
| `/` | 聚焦搜索框 |
| `N` | 新建服务 |
| `T` | 切换主题（跟随系统 → 浅色 → 深色） |
| `Esc` | 关闭弹窗 |

## 数据

所有数据在 `data/` 目录，**不需要备份整个程序目录，备份这个文件夹就够了**：

```
data/
├── portal.json      服务、用户、设置（主数据）
├── sessions.json    登录会话
├── uploads/         上传的 Logo 和图标（没人引用的会自动回收）
└── backups/         自动备份，保留最近 40 份
```

`data/` 里包含密码哈希和上传文件，已经在 `.gitignore` 里排除，不会被提交到仓库。

上传目录不会无限膨胀：每次启动和每小时各回收一次，只删「已经没有任何地方引用」的图片，而且只动 6 小时前上传的（避免误删刚传上来还没点保存的）。管理员也可以在设置面板点「清理图片」立即回收，按钮旁边会显示当前占用。

## 部署到服务器

`deploy/` 下有几个模板：

| 文件 | 用途 |
|---|---|
| `portal.service` | systemd 常驻运行 |
| `nginx-portal.conf` | Nginx 反向代理 + HTTPS |
| `frpc.toml` | frp 内网穿透（需要有公网服务器） |
| `cloudflared-config.yml` | Cloudflare Tunnel（不需要公网 IP） |

以 systemd 为例：

```bash
sudo cp deploy/portal.service /etc/systemd/system/corp-portal.service
# 按需修改里面的 User / 路径 / 管理口令
sudo systemctl daemon-reload
sudo systemctl enable --now corp-portal
journalctl -u corp-portal -f
```

注意 `portal.service` 里的 `Environment=PORT/HOST` 优先级高于 `config.json`，想统一在一处管理就把那两行注释掉。

## 版本与更新

版本号唯一来源是 `package.json` 的 `version` 字段，服务端读出来后会通过 `/api/ping` 和 `/api/state` 一起返回，页脚和设置面板底部都能看到当前版本。

设置面板底部的「检查更新」会去 GitHub 查最新 Release：

- 结果缓存 30 分钟，避免频繁请求把 GitHub 的匿名限额用光
- 发现新版本时列出更新说明和安装包下载链接
- 管理员可以直接点 **「立即更新」**：自动下载安装包、替换文件并重启服务。重启由启动器接手，**端口和模式都不变**（自定义过端口也不会掉回 8080）。`data/` 和 `config.json` 始终保留，旧文件备份到 `data/update-backup-*`，替换失败会自动回滚重启。更新完成后页面会绕开浏览器缓存重新加载，不会出现「版本号变了、界面还是旧的」
- 服务器不能访问外网时，启动加 `DISABLE_UPDATE_CHECK=1` 可以直接关掉这个功能
- 能出网但需要代理时，指定 `UPDATE_PROXY=http://127.0.0.1:7897`，或写进 `config.json` 的 `"updateProxy"`，下载安装包会走这个代理
- 更新过程写在 `data/update.log`，卡住了先看这个文件

### 发版流程

```bash
# 1. 改 package.json 里的 version，提交
# 2. 一条命令：打包 → 打 tag → 建 Release → 上传源码包和两个 exe
npm run release
```

只会打包 git 跟踪的文件，所以 `data/`、`config.json` 天然不会混进去。另外两个参数：

```bash
npm run release -- --dry              # 只打包，不发到远端
npm run release -- --notes "修了 xxx"  # 自定义更新说明（默认取最近提交）
```

凭据优先读 `GITHUB_TOKEN` 环境变量，没有就用 git 里已经存好的。

## 安全说明

- 密码用 scrypt 加盐哈希，导出数据时自动剔除哈希字段
- 上传接口校验文件头字节，改扩展名蒙混不过去；SVG 响应带 `Content-Security-Policy: sandbox`，即使内含脚本也不会执行
- 单张图片限制 6MB，仅接受 PNG / JPG / WebP / GIF / SVG
- 会话落盘在 `sessions.json`，改密码会踢掉其它设备，停用账号立即失效
- 静态文件服务做了路径穿越拦截

如果要暴露到公网，**务必**走 HTTPS 并设置 `COOKIE_SECURE=1`，否则会话 Cookie 可能在明文链路里被截。

## 常见问题

**忘记管理员密码了？**

停止服务，编辑 `data/portal.json`，把 `users` 数组里的管理员那条删掉（如果只剩这一个用户，整个数组置空即可），重启服务会按 `ADMIN_USER` / `ADMIN_PASSWORD` 重新创建管理员。

**端口被占用？**

启动时会提示。改 `config.json` 里的 `port`，或临时用 `node server.js --port 8081`。如果端口上是本程序已在跑的服务端，`npm run start:*` 会直接复用它。

**桌面客户端提示「这个服务端只对桌面客户端开放 / 只给网页版使用」？**

服务端用了 `--mode` 限制。要和浏览器共用，启动时选 `both`（`start.bat` 第 3 项）。

**改了端口，穿透打不开？**

frp / cloudflared 配置里的本地端口要同步改。
